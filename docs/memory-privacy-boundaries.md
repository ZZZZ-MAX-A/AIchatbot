# 群聊、私聊记忆与仓库隐私边界

普通聊天和群内记忆检索命令使用同一套受众规则，角色之间仍由各自数据库隔离。

| 场景 | 会话摘要 | 手动长期记忆 |
| --- | --- | --- |
| 普通群聊 | 当前群、当前角色的摘要 | 当前群的事实和偏好 |
| 私聊 | 当前用户、当前角色的私聊摘要 | 当前用户的事实和偏好 |
| SceneHub 特定三人群 | 经独立授权读取当前角色与主人的私聊背景 | 经独立授权读取该角色的主人记忆 |

普通群聊不会读取用户主体的私人记忆，也不会读取其他群的记忆。原有
`owner_only` 检索权限继续保留：非主人不会获得语义记忆检索权限。过滤在
排序和 `top_k` 截取之前执行，避免私人结果挤占本群的合法结果。

群内 `/添加偏好记忆` 与 `/添加事实记忆` 都归当前群；在私聊中执行时归
当前用户。旧的用户主体记忆保留在原数据库，不自动迁移或删除。当前没有
个人记忆的“允许在群中公开”标记，因此个人偏好也默认保留在私聊。

SceneHub 仍只绑定 `SHARED_SCENE_GROUP_ID`，成员必须恰好是主人和两位机器人。
普通互动在开始、每个角色生成之前、发送之前重新查询成员，不使用已有
成员缓存。查询失败或成员不符时停止本轮后续生成和发送。主动闲聊仍只
使用公共场景，不注入私聊背景。API 查询和实际发消息之间仍可能发生瞬时
成员变化，QQ 接口没有提供两者的原子操作。

## 提交前检查

`tmp/`、`output/` 是本地输出目录，整体忽略。正式私人设定、运行数据库、
日志继续保留在本地；示例和测试中的账号使用一致的虚构值。

仓库提供 `.githooks/pre-commit`。新克隆可用以下命令启用；已有自定义钩子
的仓库应先合并原钩子，避免替换已有检查：

```powershell
git config --local core.hooksPath .githooks
```

提交时检查实际暂存版本，拦截受保护目录、当前 `.env` 的账号和秘密值、
常见密钥格式，以及本地私人卡片的完整副本和长文本片段。检查只报告路径
和变量名称，不打印秘密值。

也可以手动运行：

```powershell
.\.venv\Scripts\python.exe scripts/check_repository_privacy.py
.\.venv\Scripts\python.exe scripts/check_repository_privacy.py --tracked-worktree
```

第二条命令检查已跟踪文件的当前工作版本，也被仓库隐私回归测试调用。
这些检查不检查远端或完整历史。脱敏当前工作文件不会清除旧提交中的账号
标识；本次不改写历史、不重建索引，也不修改任何现有聊天数据。

代码修改在机器人进程重启后生效。重启前应先运行记忆、RAG、SceneHub 和
仓库隐私相关测试。
