## 读取与优先级

Bot 和控制台继续在首次导入配置模块时读取项目根目录 `.env`，保持 `python-dotenv` 的默认行为：
已存在的进程环境变量优先于文件，显式空值也不会被文件覆盖。
`load_config()` 随后读取一次进程环境快照，不修改环境、不重新加载文件。
文件修改需要重启相关进程；本阶段没有热重载或跨进程配置同步。

`load_config(environ=...)` 支持显式配置映射，用于隔离的预检和测试。
解析上下文使用 `ContextVar`，并发读取不同映射不会串用配置。
配置来源记录的是输入状态：进程/映射中存在、显式空值、缺失而使用默认或继承。
因为 `.env` 在导入时已合并进环境，来源元数据不声称能区分某字段最初来自文件还是进程。

| 输入 | 处理方式 |
| --- | --- |
| 布尔值缺失 | 使用既有默认值 |
| 布尔值合法 | 接受 true/false、1/0、yes/no、on/off，不区分大小写 |
| 布尔值拼错或显式空值 | 汇总为错误并停止加载，避免保护开关被误关 |
| 普通数字缺失或空值 | 使用既有默认值 |
| 普通数字格式错误，或浮点数为 NaN/Infinity | 汇总为错误并停止加载 |
| 既有能力参数数字格式错误 | 保留原来的 0 哨兵处理，并报告警告；能力的范围约束继续由相应入口执行 |
| 凭据、接口、模型显式空值 | 保留空值，不偷偷继承旧变量或其他模型 |
| 专用视觉/图片字段缺失 | 保留原来从人格配置继承的规则 |

错误只包含字段名、错误类型和固定说明，不回显错误原值。
本阶段没有全面重写所有数字的业务范围规则；模型路由和各能力已有的正数、阈值与跨字段约束继续生效。
`PORT` 增加统一的整数与 1–65535 范围检查，并供启动、诊断和巡检使用。

## 兼容与迁移

- `OPENAI_API_KEY / BASE_URL / MODEL / TIMEOUT_SECONDS` 保持不参与实际聊天配置读取，新增明确迁移提示。
  请显式迁移到对应 `AIKE_LLM_*`；只填旧变量不会自动恢复聊天，也不会覆盖已设置的新变量。
- `CHAT_LLM_*` 保持兼容读取；显式设置这些字段时提示其不参与生产聊天路由。
- 默认聊天、人格聊天、摘要、MainAgent 继续使用上一阶段确定的独立路由。
- 当前视觉使用固定云端提供方和模型；设置 `VISION_PROVIDER` 或 `VISION_CLOUD_MODEL` 会收到无效覆盖提示。
- 无法解析的可信文件路径允许列表项仍被忽略，并新增字段级提示；人格绑定错误仍按既有边界停止对应路由。

两份 `.env.example` 已统一为同一内容，补齐 ChatGraph、人格、摘要、云端视觉、SceneHub 和 RAG 配置。
测试通过 AST 核对配置加载器读取的字面量字段，并检查模板缺项、重复项和两份模板的一致性。
模板值是部署示例；实际加载默认值仍由代码定义。本次没有覆盖用户的 `.env`。

## 只读检查

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/check_configuration.py
.\.venv\Scripts\python.exe scripts/check_configuration.py --json
.\.venv\Scripts\python.exe scripts/check_configuration.py --require-chat
```

默认命令校验配置语法并报告线路与固定绑定状态；`--require-chat` 在默认聊天线路缺项或账号固定绑定未就绪时返回非零退出。
只读预检使用包壳加载配置模块，避免执行 Bot 插件的 matcher 注册、数据库初始化或客户端导入。
它不读取私人卡片、聊天记录，不连接数据库，不启动服务，不探测外部接口。
JSON 使用 ASCII 转义，避免 Windows PowerShell 与 Python 输出编码不一致破坏解析。

QQ 配置告警与控制台诊断能显示新增的配置提示或提示数量。
配置语法正确、线路配置完整、服务可达、端到端功能可用是不同证据；预检不把配置完整等同于服务在线。

## 启动与巡检依赖

`start.ps1` 先读取共享配置预检，再检查配置端口归属；仍在启动任何服务之前阻止重复 Bot。
Ollama 的需求按已启用能力分别判断：云端视觉不需要 Ollama；Ollama 向量检索和可选原生人格模型需要它。
共享报告按本机地址生成所需模型计划。标准本机端点可以走既有 ensure 流程，远程地址或自定义端点不会自动启动本机服务。

`ensure-ollama.ps1` 默认也读取共享配置；启动脚本可直接传入已解析的端点与模型计划。
仍保留连接拒绝才允许启动、健康服务缺模型时停止而不重启、不自动下载模型，以及 `-NoStart` 的边界。
独立调用 ensure 时默认处理第一组本机端点；启动脚本遍历标准本机计划。其他端点需独立管理。

`reliability_inspection.py` 使用同一配置解析器、配置端口和能力依赖列表。
它只探测本机端口，远程依赖报告为未探测；配置语法错误时不进行端口或数据库检查。
`diagnose.ps1` 移除 `import bot` 检查，SQLite 改为 `mode=ro` 打开，不再因诊断创建缺失数据库。
