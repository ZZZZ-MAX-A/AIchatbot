# 维护入口与重复实现收敛

更新日期：2026-10-11。

本轮集中处理重复展示、重复确认交互和固定诊断的重复 HTTP 校验。现有工作区改动保留；没有提交、推送、删除记忆、启动 Bot 或调用真实模型。

## 日常维护入口

| 要解决的问题 | 主要入口 | 保留的备用入口及职责 |
| --- | --- | --- |
| 账号绑定什么人物、角色卡、记忆库、模型和音色 | Web 配置页的账号人格面板 | QQ 配置与角色卡命令；Web 不可用时仍能查看 |
| 当前是否有异常或待处理任务 | Web 首页的总体判断与异常清单 | QQ `/状态`；查看聊天进程实际状态 |
| 执行固定功能检查 | Web 诊断页 | QQ `/诊断`；两者的探测范围和运行进程不同 |
| 固定账号所属人格库的计数与策略 | Web 记忆页的“记忆维护范围” | QQ `/记忆状态`、`/RAG状态`；按当前事件的人格范围执行 |
| 历史失败是否恢复或反复发生 | Web 可靠性页 | `inspect-reliability.ps1`；离线查看结构化事件 |
| 启动前配置是否合法 | `check_configuration.py` | `diagnose.ps1` 调用它，并补充本机进程、端口、默认数据库与日志检查 |

账号人格面板继续完整显示聊天模型、视觉模型、独立记忆库、音色参考试听、场景例外，以及默认人格/独立人格的能力差异。旧共用设置保留在已有折叠区。本轮没有增加 MainAgent 人格配置。

## 本轮收敛

1. 首页移除重复渲染的 Bot、诊断、记忆、最近错误四块明细。首页仍读取诊断数据并判断全部八个区块的读取异常；完整证据集中在诊断页。
2. 首页与诊断页共享 `app/diagnosticSections.ts` 区块清单，避免一处增加区块而另一处漏报。
3. 诊断页直接显示已启用的语音和百炼视觉检查；项目文档 RAG、所选人格库 MemoryRAG 一致性、Main LLM 固定合同检查放入“高级维护检查”。展开不会执行动作，固定确认步骤仍保留。
4. 原始配置、统计、图观测和运行边界合并到“技术证据与运行边界”。默认折叠；快照读取异常时自动展开。高级检查出现失败、待关注或正在运行结果时也自动展开，成功后保留用户已展开的状态。
5. 五个诊断面板共用 `ManualDiagnosticConfirmation`。各检查的固定问题、外发说明、语音生命周期说明和执行边界仍分别保留。
6. 六个固定运行接口共用 `run_fixed_manual_diagnostic`，统一核对独立启用开关、同源 loopback、动作标识、会话 cookie、JSON 类型和精确确认对象，再执行固定执行器。各路径、开关、确认值和返回资源不变。禁用的动作不会解析执行器。
7. QQ 帮助改为按状态、配置、记忆、摘要、缓存、权限、表情分组；别名集中说明。现有命令匹配、权限检查和执行逻辑保留。

## 需要保留的区别

- 只读配置快照说明本地装配；实时探测说明单次调用；历史可靠性说明过去的成功/失败。三者不能互相代替。
- 配置页的参考音色播放与诊断页的真实合成听检不同：前者读取现有 WAV，后者执行一次固定合成并质检。
- 项目文档检索与私人记忆索引核对各有职责：前者可调用 embedding，后者只读核对所选人格库结构，不检索私人正文。
- 音频/图片预览和质检接口具有额外的文件、运行 ID 和审核合同，保留独立校验。
- QQ 和 Web 的运行进程及依赖不同；删除 QQ 备用命令会削弱 Web 离线时的排障能力。
- Web 记忆统计、诊断技术证据和 MemoryRAG 一致性检查统一按固定账号绑定选择人格库；展示当前人物、记忆库及会话命名空间。每次只维护一个人格库，计数不代表全部人格合计。

## 统一记忆维护范围

范围复用固定账号 → 人格/角色卡 → 持久记忆库的现有解析规则。网页只选择维护对象，不切换账号绑定或角色卡。默认人格仍使用现有默认库；独立人格使用独立人格库。群聊/私聊属于同一人格库的不同受众，会话隔离与检索过滤继续有效。

- 记忆页、诊断页共用账号选择器与设置快照。URL 的 `memory_account` 保留本页所选账号。没有显式选择时，只能采用唯一明确绑定的旧库账号；未知账号、异常绑定、角色卡缺失或仅进程内记忆不回退到其他库。
- 记忆范围请求只接收 `bot_self_id` 与 `scope_revision`，拒绝任意库路径、重复/残缺参数和额外参数。没有有效选择时，诊断页显式使用 `skip_memory=true`，只读取其他区块，不暗中查询默认库。执行前重新验证账号、角色卡、持久模式、路径和相关索引配置；旧确认失效后必须刷新。
- Web 计数使用单个 SQLite 只读连接与固定聚合 SQL，不初始化或迁移数据库，不投影正文。记忆 RAG 计数仅统计 `semantic_memory`，不混入项目文档。
- 缺失库、结构不完整、链接重定向或读取失败明确报错；诊断页保留其他区块，单独标记记忆不可读取。切换账号取消旧请求与旧确认，旧结果不会覆盖新范围。
- 一致性结果按账号和配置版本保留当前进程中的最近记录，控制台重启后清空。手动诊断仍共用互斥锁；没有增加重建、修复、删除或模型调用。QQ 维护命令继续按接收消息的账号解析范围。

## 后续维护优先级

| 优先级 | 改进区域 | 处理方式 |
| --- | --- | --- |
| 高 | `__init__.py` 中大量维护处理器和报告拼装 | 分离报告、命令注册、权限与执行适配；保留现有命令名称，复用同一业务执行器，逐组迁移 |
| 中 | 旧本地视觉诊断与现用云视觉诊断 | 核对 CLI、HTTP 合同、历史结果和外部调用者后，标记旧路径退役；当前仍保留兼容接口，不把不可见等同于无人使用 |
| 中 | CLI 与 Web 的统计和配置报告 | 合并纯配置/统计构建器；保留 CLI 启动前检查和 Web 运行时展示的不同职责 |
| 中 | 历史设计文档与当前操作手册 | 操作手册作为日常入口，历史文档标注阶段与后续替代说明；避免按旧页面说明重复新增维护按钮 |

记忆维护范围已统一。下一步优先处理维护处理器拆分，再评估删除兼容入口。不能单凭名称相似删除不同人格、不同数据范围或不同副作用的功能。

## 验证与部署

新增接口合同交叉检查覆盖六个固定动作，确认错误会话、来源、动作标识、其他工作流的确认值、附加请求参数、非法 JSON 不会触发执行；禁用和忙碌状态的响应保留。

前端验证覆盖首页保留异常判断和跳转、默认折叠、异常自动展开、展开不执行动作，以及原有确认、试听、质检和互斥流程。

重复维护收敛的验证存于忽略 Git 的 `tmp/maintenance-consolidation-20261011/`；记忆范围统一的测试、差异和清单存于 `tmp/memory-maintenance-scope-20261011/`。后端新接口由本地 Owner Console 进程重新加载；不重启 QQ/Bot，也不执行在线模型验收。
