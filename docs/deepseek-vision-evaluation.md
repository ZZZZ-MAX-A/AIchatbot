# DeepSeek 图片能力与默认人格聊天配置实测

检查时间：2026-10-18（北京时间）。按主人要求使用默认人格当前聊天线路的配置，独立调用 API 测试。

## 结论与模型名称

当前配置 `deepseek-flash` 可以正常进行纯文本和图片请求：共 7 次请求均为 HTTP 200，
返回模型名为 `deepseek-flash`，结束原因为 `stop`，没有空正文、截断或请求超时。
六个图片样本的主要场景、界面信息或色块布局与输入对应；这不代表细节无误或稳定性已充分验收。

当日官方模型与价格页面明确要求使用 `deepseek-flash`，版本对应 `DeepSeek-V4.1-Flash-1017`。
旧名称 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可调用，但对应旧模型已下线，
由最新 Flash 承接并按 Flash 计费。因此本次改名符合官方建议，不能把旧名直接判为接口错误。

## 请求与证据范围

通过项目真实配置加载器及聊天路由解析器读取配置，不在报告中保存密钥：

| 项目 | 实际设置 |
| --- | --- |
| 线路来源 | legacy，默认人格聊天线路 |
| API 主机与路径 | `api.deepseek.com/chat/completions` |
| 请求及返回模型 | `deepseek-flash` |
| 思考强度 | `reasoning_effort=max` |
| temperature | 请求传入 0.7；官方说明思考模式下忽略此参数 |
| 请求超时 | 60 秒 |
| SDK 自动重试 | 测试显式设为 0，以便记录单次调用 |
| 输出预算 | 测试显式设为 `max_tokens=4096`，包含思考消耗 |
| 图片格式 | user 消息中的 text + image_url 内容数组，PNG Base64，`detail=high` |
| 图片提示词 | 项目现有 `VISION_PROMPT`，不附带角色卡、聊天历史、记忆或百科 |

这次复用聊天线路的端点、凭据、模型及思考设置，使用独立图片能力探针发送请求。
没有执行完整角色聊天流程，也没有验证百科工具、多轮工具回传、QQ 图片下载或最终角色回复。
正式普通聊天通常不显式设置 max_tokens；4096 是本次诊断预算，不是修改后的生产参数。

HTTP 请求钩子核对了实际发出的模型、思考强度、输出预算、温度与路径；
六张图均从实际请求体解码，SHA256 和字节数与源图片一致。
返回用量包含实际 reasoning_tokens，确认本次请求确有思考消耗；不保存思考正文。
供应商未提供独立 image_tokens 字段，不能把缺失字段解释为没有输入图片。

但供应商、预算及测试时刻不同，不能当作严格性能基准。

## 当前接入边界

- 修改默认人格聊天模型名不会自动切换图片预处理。独立测试时默认人格正式识图走阿里百炼，独立人格走 Grok。
  主人随后要求切换独立人格：代码和本地配置现已接入 DeepSeek，待 Bot 加载生效，默认人格仍走阿里。
  切换与正式入口的独立验证见 [当前视觉配置](vision-diagnostics.md)。
- 项目当前单图上限为 5242880 字节（5 MiB）。10-01 样本为 6502963 字节，正式预处理会先拦截。
  本次仅测试时直传原图核对 DeepSeek 能力，没有放宽生产限制。
- 当日官方图像指南说明 Base64/外部 URL 单图上限 32 MiB、请求体上限 48 MiB；因此 5 MiB 是项目限制。
- 图片内容放在 user 消息中；官方说明 Chat Completions 的 system/assistant 消息携带图片会返回 400。
- 当前路由通过模型名前缀或官方主机识别 DeepSeek，`deepseek-flash` 改名不会绕过既有供应商参数处理。
- 本次只验证有限样本的一轮请求，没有证明所有场景、长历史或工具调用都可用。
