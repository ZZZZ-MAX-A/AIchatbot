# B 站对话留存与 QQ 补充背景

2026-10-22：按主人确定的规则实现 B 站原文留存、最近 3 轮背景，以及最多 5 条未注入消息的独立语义召回。
现有 B 站按视频元数据检索 QQ 记忆的 RAG 保留。本文描述的是另一方向：QQ 读取 B 站实际发生的对话。

同日新增 [今日观影小记](bilibili-daily-note-runbook.md)：当天已核验的字幕阅读内容与角色感想也可进入同一背景，
包含未推荐分享的视频。小记独立存放、隔日替换，不占私信轮次、不加入长期 RAG，共用本文的总预算。

## 已实现的范围

- B 站原文保存在仓库外连接器私人目录的 `history.db`，不写入 QQ 的 `messages`、摘要、状态卡、手动长期记忆或 RAG 表。
- 使用现有固定身份映射，同时限定双方 B 站账号、QQ 账号、主人、人格、角色卡、QQ 会话及存储模式。
- 仅绑定主人的 QQ 私聊、持久记忆路径读取；其他用户、群聊、其他机器人或人格、临时记忆均不读取。
- 真实视频分享在平台接受发送后保存发送原文。预览、草稿、发送失败或结果未知不记录成成功互动。
- 主人消息及回复的留存 API 已提供，但 B 站私信接收器尚未实现，本次不启动接收轮询或后台刷视频。

## 一轮的含义

主人一次发言及其对应实际回复使用同一个 `round_key`，连续消息或多段回复可归在同轮。
默认人格主动分享没有主人发言，独立算一轮，不补造 user 消息。
最近 3 轮按该轮最新消息的来源时间选择，恢复原时间顺序，不按最后插入数据库的时间猜测新旧。

原文完整保存。模型背景中的原句允许受预算裁切，显式标记 `truncated`；这不是改写原文或生成正式摘要。
预算紧张时，先为每轮分配展示位置，再放同一轮更多消息；极小预算可能少于 3 轮或完全不注入。

## QQ 注入位置与语义检索

QQ 原有记忆组装完成后，通过一次只读 B 站快照生成独立背景，插在第一条 QQ user/assistant 历史之前。
QQ 的原文条数、正式摘要数量、当前场卡、人工长期记忆及原有 RAG 的 top-k/字符预算不改变。
本轮可信时间及本次 QQ 消息仍在后面；B 站材料有历史来源声明，不作为本轮指令。

最近 3 轮优先展示；独立 RAG 使用本次 QQ 消息做查询，只从未在近期背景实际展示的消息中选择最多 5 条。
同一消息不会同时作为近期背景和召回结果出现；近期消息因预算完全没展示时，允许作为召回候选。
检索单位是消息，不是 5 个视频或 5 轮对话；原有 QQ 召回的 5 条不会因此被占用。

索引位于 B 站自己的数据库，使用既有 embedding provider/model 和相似度门槛。
受众隔离、源正文 hash/有效状态、向量有效性检查先于排序。撤回或正文已变而索引过期的记录不注入。
无命中不补无关旧消息；QQ 请求只读已有索引，不自动给历史全文重新向量化。
B 站查询 embedding 最多使用 3 秒 timeout，使用支持的单次请求入口，失败保留近期背景，不重试整个聊天。
新分享归档后尝试增量建索引；索引失败不丢原文，不把已成功发送改成失败，不重发私信。

## 时间与时效性

保存 `occurred_at`、`recorded_at` 及 `time_kind`。展示复用现有北京时间/相对间隔格式，每轮读取时重新计算。

- `platform_sent`：来自平台的原消息发送时间。
- `send_confirmed`：本地收到发送成功确认的时间，不代表主人阅读时间。
- `recorded_only`：原发送时间未知，只能展示记录时间。
- `send_attempt`：旧发送台账保存的尝试时间，不能冒充准确发送或送达时间。

历史中的今天/明天/刚才按原消息时间理解；旧情绪、身体状态及未确认约定不自动延续到当前 QQ 场景。
本次未把 B 站写入 QQ 重逢台账，未修改原有重逢强度、计时或场景压缩规则。

## 独立预算

默认 B 站背景合计最多 1200 个粗估 token，且不超过 QQ 近期 user/assistant 原文（含时间标签）加当前文字的粗估量的 20%。
角色卡、QQ 系统提示、正式摘要及其他背景不用于放大这个相对额度。
上限包含 B 站背景的声明、JSON 字段、时间标记、原文片段与今日观影小记；各部分共用上限，不是各 1200。
有旧记录待检索时，先约分配 2/3 给近期窗口，剩余给召回；没有命中时可把空间还给近期窗口。
只裁切或省略 B 站背景，不截断 QQ 原有消息；不保证每次都能放下完整 3 轮及 5 条原文。

估算沿用 `ceil(UTF8 bytes/3)`，不是模型供应商实际分词。在同一估算尺度下，20% 相对上限使 B 站占 QQ 原文加 B 站材料的比例不超过约 16.7%。
这控制输入篇幅，不等同于模型注意力占比或效果保证；真实回复质量和供应商 token 尚未进行聊天模型实测。

可选配置已加入两个 `.env.example`，本机未重写 `.env`，缺省值直接生效：

```dotenv
# 控制 QQ 是否读取 B 站背景，不会删除已归档原文。
BILIBILI_HISTORY_ENABLED=true
# 仅控制此独立 B 站历史检索，不改变原有 QQ RAG 或 B 站读取 QQ 的 RAG。
BILIBILI_HISTORY_RAG_ENABLED=true
BILIBILI_BACKGROUND_MAX_TOKENS=1200
BILIBILI_BACKGROUND_QQ_RATIO=0.20
```

## 本地命令

```powershell
# 仅显示条数和索引状态，不打印原文、账号或路径；不创建不存在的历史库。
.\.venv\Scripts\python.exe scripts\bilibili_history.py status

# 只回填私人预览中有匹配成功发送台账的原始消息，不改写报告，不发私信。
.\.venv\Scripts\python.exe scripts\bilibili_history.py import-sent

# 增量索引该 B 站库，每次最多 64 条；有积压可再次执行。仅调用配置的 embedding 服务。
.\.venv\Scripts\python.exe scripts\bilibili_history.py index

# 用 QQ 当前真实原文验证注入位置/预算，仅输出计数与用量元数据；默认不做语义查询。
.\.venv\Scripts\python.exe scripts\bilibili_history.py context-status
```

`context-status --query "查询文字"` 可以验证独立检索，会在有候选及预算时请求 embedding，不调用聊天模型。
`ChatPromptContext.bilibili_memory_status` 携带条数、预算、截断量和检索状态，不携带私聊原文。
映射缺失或变化、数据库损坏、索引缺失或 provider 失败均不会清空 QQ 上下文；错误元数据不回显异常原文。

## 本机验收边界

本轮从既有私人报告与成功台账匹配回填 1 条实际发送原文，跳过 4 份不符合条件的报告；原报告未改写、未重发。
只对这 1 条记录完成一次本地 embedding 索引。只读上下文预览注入 1 轮、1 条消息，序列化背景粗估 398 token。
因该记录仍在近期窗口，独立 RAG 没有旧消息可召回；最多 5 条及去重已用合成数据测试。
组合回归共 451 项，450 项通过、1 项因本机文件链接能力限制跳过；新增留存/QQ 入口/发送归档测试共 30 项。
未调用真实聊天模型、请求 B 站、发送新私信、重启 QQ Bot 或修改角色卡。
运行中的 QQ 进程需下次正常重载才能使用新入口；不能把只读预览通过等同于 live 聊天效果验收。
