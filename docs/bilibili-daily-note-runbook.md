# 默认人格今日观影小记

同日后续：小记已接入 [自动浏览进程](bilibili-autobrowse-runbook.md)，每日最多 3 条主动分享亦已实现。
以下验收记录中的“调度仍需实现”仅表示此前阶段，不代表当前代码状态；是否已启动以进程 status 为准。

2026-10-22：按主人要求复用已经付出模型用量的视频理解结果。
值得分享和读过字幕但未推荐的视频，都可以形成当天的简短内容与角色感想，供 QQ 回答今天看了什么或自然接续相关话题。

## 写入与内容依据

`scripts/bilibili_browse.py preview` 每轮模型处理结束后，独立更新小记，默认预览不发送私信。
只有 `summarized` / `not_recommended` 且字幕身份、引用和主题一致性重新通过校验的结果进入小记。
保留视频标题、BVID、阅读完成时间、内容要点、角色感想、是否值得分享及字幕覆盖标记。
只刷到标题/封面、未选中读取字幕、无字幕、风控、来源错配或总结失败，不算已经了解视频内容。
一轮中有其他视频失败时，已经核验成功的视频仍可留在小记。

感想使用同一次 `summarize` 请求新增的 `viewing_impression`，不再调用一次模型写日记。
这仍会增加少量任务说明及感想输出 token，不代表零新增 token；实际成本以供应商返回用量为准。
旧结果缺少感想时不补造，也不把待发送草稿冒充个人感想。
没有从旧报告自动补写小记或触发重新浏览。

## 当日更新与隔日替换

按北京时间（Asia/Shanghai）自然日管理，每轮增量合并今天的记录，同一 BVID 当天去重，较旧结果不覆盖较新结果。
这让当天随时询问都能用到最新结果，不必等晚上另跑一次汇总。
保存位置是仓库外连接器私人目录中的 `daily-note.sqlite3`，每个固定身份范围仅一行当前小记，不保存逐日版本。
小记渲染为最多 600 字符的短文，较新视频优先；正文摘录会标省略，总视频数与展示视频数分开记录。
超过短文或上下文预算时，只提供有标记的部分记录，模型不能声称已列出全部视频。

凌晨以后，昨天的小记立即不参与 QQ 注入；即使今天还没有刷过，也不会把昨日经历当成今天。
下一次预览写入时用新的一天替换旧记录，没有定时唤醒、午夜模型调用或历史小记 RAG。
已有诊断报告和真实私聊归档继续按原规则保留，不因小记替换而删除。
若视频后来在 QQ 中真正聊到，这些 QQ 对话仍按原记忆规则留存，不属于小记历史版本。

## QQ 的读取与预算

复用现有固定跨平台身份校验，只向绑定主人的同一默认人格 QQ 持久私聊提供小记。
`viewing_today` 与最近 3 轮 B 站私聊、最多 5 条独立召回处于同一补充背景中，位置仍在 QQ 近期原文之前。
小记本身不写入 B 站私信轮次，不建立语义索引，不写入 QQ 原文、正式摘要、状态卡或人工长期记忆。
当日体验不代表已发送私信、已与主人讨论、看过画面或完整视听观看；实际发送记录仍由原私聊归档证明。
提示允许在相关话题中自然提及自己的阅读感受，不要求主动播报小记。

继续共用原 B 站背景总上限：默认最多 1200 个粗估 token，且不超过 QQ 近期原文加当前文字的 20%。
小记正文及自身说明先限制在可用空间的约 1/3、最多 300 粗估 token，字段开销也计入最终总帽。
剩余空间按原近期/RAG 规则分配，不扩大原 B 站预算或裁掉 QQ 原文。预算不足允许不注入。
QQ 只读已有小记，不调用聊天模型生成日记，不因读取小记发起 embedding。
小记损坏不影响仍可读取的私信背景；写入失败仅记录脱敏状态，不重发视频或重跑模型。


本轮仅进行离线合成数据验收，没有新增真实浏览、模型请求、私信或运行进程重启。
新的真实预览才会生成该次阅读的小记；运行中的 QQ 需正常重载后才能使用新增读取逻辑。
自动浏览、每日分享额度与私信接收仍需要分别实现，不能把此模块视为已经启用自动刷视频。
