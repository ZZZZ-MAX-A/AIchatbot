# 每轮北京时间与重逢

## 已确认的业务规则

- 每次角色聊天请求都带有本轮北京时间、日期、星期和 UTC+8。时间读取本机时钟，
  不依赖联网搜索。普通聊天、图片描述后的聊天、语义语音回复和专用群聊角色回复共用
  `ask_llm` 的时间边界。明确时间问题的事实校验复用该轮快照。
- 时间和重逢提示仅用于本轮模型请求，不写入消息、摘要、长期记忆或角色卡。
- 以该账号、人格上次成功回复主人的时间，到主人本次消息时间计算间隔。
  同一人格在普通群聊、专用群聊和私聊中的实际成功回复均计入。
- 时间记录按账号、人格、主人分别隔离。群聊与私聊共享的仅是成功互动时间和来源类别，
  不因重逢功能共享原文、摘要或记忆。重逢先只在主人私聊触发。
- 机器人主动消息、自主聊天、回复其他群友、应急通知、纯朗读/重播语音、
  模型空回复的错误提示和视觉失败提示不更新成功互动时间。
- 第一条成功回复接住重逢，后续情绪随互动延续，不反复提醒离开时长。
  完全发送失败不更新；分段回复已有一条有效消息成功发出就记录，
  后续分段失败不会让下轮再次按久别触发。

## 时间与情绪

| 实际间隔 | 情绪程度 |
| --- | --- |
| 少于 3 小时 | 正常续聊 |
| 3～12 小时 | 轻微 |
| 12～24 小时 | 明显 |
| 1～3 天 | 更强 |
| 3～7 天 | 较强 |
| 7～14 天 | 久别，继续增强 |
| 14 天及以上 | 达到情绪上限，保持两周尺度 |

跨日不额外增加强度。昨晚 23 点到今早 8 点是 9 小时，保持轻微重逢，
结合早晨自然回应；不能根据间隔断定主人睡过觉。

只封顶情绪，实际间隔不封顶。30 天未聊时提供真实的约 30 天间隔，
不能因为情绪档位而说成两周。角色可以自然说几天、一个星期或好久，
表达必须与本轮事实一致，不要求机械播报秒数。

另有窄范围的发送前纠正：实际间隔至少 21 天，本轮重逢回复却明确说“两周/14天没来”
等离别时长时，将该时长改为实际已过的整天数。不会改写整段角色表达，
不处理无关日程或明确否定的比较；任意自然语言时间说法仍需在线验收。

长间隔可以体现强烈思念、适当委屈、撒娇和主动亲近。按现有角色卡生成，
不注入固定台词，不固定泪光、动作或句式，不强迫每次直说“我有点委屈”。
结合当前消息和近期回复变化表达；不责怪、不强迫解释去向，
不编造离开期间的经历、约定、共同回忆或现实操作。

## 上下文衔接

- 明确或能可靠指向旧话题时，自然续接已经确认的信息和未完成内容。
- 新话题优先回应本句，旧话题仍可恢复；纯问候先接住重逢。
- “继续”有多个可能指向时简短确认，不自行选一个。
- 旧“今晚/明天”、地点和身体状态需结合本轮时间与意图重新判断。
  明确要求续写才恢复旧角色扮演场景，不能默认恢复旧动作或成人场景。
- 事实任务、疲惫或严肃倾诉优先回应本句，将情绪融入回应。
- 重逢不清空、不重写记忆。仍以现有短期历史和可靠记忆提供旧话题信息；
  用户主动清除的内容不从互动时间库恢复。

## 存储与发送

`data/chat-interactions.db` 是独立的 SQLite 运行数据文件，在首次成功互动时建立。
`owner_interactions` 仅包含 `bot_self_id`、`persona_id`、`owner_id`、
`succeeded_at`、`source` 五个字段，没有聊天内容、群号或记忆字段。
时间保存为带时区的 UTC，模型事实和诊断展示转换为北京时间。

读取缺失库不会创建数据库。普通记忆清理、话题切换和重启不会删除互动记录；
人格记忆库的 ContextVar 路由也不会改变这个时间库的位置。
新版本首次部署没有可靠的已发送时间时，先建立基线，不能把历史消息行
直接当成成功送达凭证。基线建立前不编造重逢间隔。

普通主人群聊和私聊按账号共用互动锁，同时保留原有会话锁。
专用群聊以固定顺序取得两个账号的互动锁，分别记录真正成功回复的角色。
自主聊天和应急通知不走成功互动回调。
语义语音在语音发送成功后记录；纯朗读和重播不记录。

OneBot 消息时间保留本次消息时间，用于排队消息的间隔计算。
若消息到达时间早于刚完成的回复时间，不再次触发。
时间库错误只记入诊断，不把已经送达的消息改判为发送失败。

## 配置与诊断

- `BOT_TIMEZONE`：当前支持 `Asia/Shanghai`，默认即北京时间。
- `ENABLE_CHAT_REUNION`：控制重逢提示，不影响每轮时间事实注入。
- `CHAT_REUNION_MIN_GAP_HOURS`：兼容现有配置，默认 3。
- `CHAT_REUNION_OWNER_PRIVATE_ONLY`：保留兼容字段；当前业务范围固定为主人私聊，
  旧配置为 false 也不会向非主人开放重逢提示。

现有聊天路由观察中增加 `Time`、`Reunion` 信息：本轮北京时间、上次成功互动时间、
本次消息时间、实际间隔、档位和状态。状态包括未建立基线、低于阈值、已注入、
排队/未来时间、范围外及存储错误。仅包含时间和固定状态，不包含对话原文。

## 验证边界

本地测试使用临时数据库、假发送器和假模型端点，验证时间注入、分档、身份隔离、
成功/失败发送、部分发送、并发锁、队列消息及专用群聊回调。
模型是否自然表达足够的思念、委屈，以及对旧话题的实际理解，需要后续统一在线验收；
单元测试不会将某句台词作为必须生成的结果。
