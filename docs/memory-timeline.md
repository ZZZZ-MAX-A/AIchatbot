# 记忆时间线

2026-10-19：在每轮北京时间注入的基础上，给记忆增加时间元数据。适用于默认人格和独立人格的现有独立记忆库，不扩大记忆读取受众。

## 时间的含义

| 内容 | 时间来源 | 模型看到的含义 |
| --- | --- | --- |
| 用户消息 | OneBot `event.time`，有效且不晚于接收时钟 | 消息发送时间 |
| 机器人文字回复 | 首个文字气泡发送接口成功后补记 | 回复首段发送确认时间；不保证后续气泡全部送达 |
| 语义语音回复 | 语音发送接口成功后记下，保存对话后补回 | 同一回复发送确认时间字段；接口成功不等于客户端已听到 |
| 旧原文或无有效发送时间的记录 | 原有 `created_at` | 记录时间，明确注明非发送确认 |
| 正式摘要 | 摘要 `created_at` + 原消息端点时间 | 摘要生成时间和原消息时间范围分别显示 |
| 场景状态卡 | `created_at`、`updated_at` + 原消息端点时间 | 状态卡生成、更新时间和原消息范围分别显示 |
| 人工长期事实与偏好 | `created_at`、`updated_at` | 记忆创建、维护时间，不是事实发生时间 |
| 语义检索记忆 | 当前人格库中的源记录；缺失时使用 `source_version` | 源摘要/记忆的时间，不使用向量入库时间 |
| 临时人格原文 | 进程内记录时间、平台时间、发送确认 | 与持久原文相同的时间说明，重启仍按原设计清空 |
| 三人群公共场景缓存 | SceneHub 创建事件时的时钟 | 场景记录时间，不能当作平台精确发送时间 |

内部使用带时区的 UTC ISO 时间；提示中转为北京时间（UTC+8），并在每次构建上下文时计算相对间隔。
例如同一回复刚读取时可以显示 `2026-10-19 08:00:00 北京时间（5分0秒前）`，几天后再次读取会显示新的天数。
时间标签不写入原消息正文，也不把“几天前”存入向量内容，因此无需重建既有索引。

## 摘要与事实边界

摘要保存覆盖原消息的起止时间，之后自动压缩删除原文时仍能保留该范围。
场景状态卡也保存来源范围，并将其与生成/更新时间分开。
范围表示来源消息的首尾时间，不证明摘要中的每个事实都发生在这个范围内，也不证明每条回复已完整送达。

摘要输入带时间；摘要提示允许保留明确且相关的事件日期，禁止将消息时间、摘要生成时间和相对间隔变成永久事件事实。
历史中的“今天/明天”按对应消息时间理解；无法确定时不猜测。
真实聊天时间不自动替换角色扮演的故事时间，情绪和重逢强度继续服从已有重逢规则及角色卡。

长期记忆没有可靠事件发生日期时，只显示创建/维护时间，不从文字中自动猜日期。
检索到尚未同步的旧版人工记忆时，显示索引内容对应的 `source_version`，并注明原记忆已有更新。
时间元数据不能保证模型完全遵守，也不代替事实校验、日程或提醒系统。

## 旧库兼容与生效

Schema 从 7 升为 8，新增：

- `messages.occurred_at`、`messages.time_kind`；原 `created_at` 保留。
- `session_summaries.source_start_at`、`source_end_at`。
- `gap_scene_summaries.source_start_at`、`source_end_at`。

升级通过原 `ensure_database()` 在下次载入/使用对应库时执行。时间列升级有保存点，并在检查列前取得写锁；重复执行不重复添加。
不删除或重写旧正文。只在升级时，用同一会话、同一消息 ID 的现存原文恢复摘要端点；已删原文不能倒推。
无法恢复时显示 `未知（旧原文时间未保留）`；部分端点缺失则单端显示未知。
旧消息默认标记记录时间；无法追溯过去的精确发送成功时间。
非法或没有时区的历史时间显示未知；未来时间提示核对时钟。

无需增加 `.env` 项。运行中的 Bot 需要重新加载本次代码后生效。
本次开发未打开或升级生产记忆库，未重启 Bot，未调用真实模型或发送 QQ。

消息持久化与发送确认、摘要压缩删除源数据、状态卡更新、人格隔离、RAG 源版本与只读退化、不重复向量化、临时历史和语义语音。
配套回归覆盖记忆、路由、群私聊权限、三人群、图片/语音、表情链路和重逢；测试不加载实际 `.env`。
