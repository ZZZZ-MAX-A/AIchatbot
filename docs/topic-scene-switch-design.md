# 换话题 / 场景重置设计合同

状态：Phase 1 已实现（待 QQ 验收）
日期：2026-08-23
范围：主人私聊（默认人格 / 独立人格等隔离人格优先）；不默认覆盖三人群 SceneHub
关联：`compressor.py`、`memory.clear_session`、`session_summaries`、`gap_scene_summaries`、私聊节拍软规则

---

## 1. 一句话目标

主人在不删除长期记忆、不整库清档的前提下，通过自然语言或明确命令结束当前短时场景，把近期原文压成一条场景摘要，并让下一轮对话以“新话题 / 新场景”开始。

---

## 2. 要解决的问题

| 现状问题 | 说明 |
|---|---|
| QQ 无法真正“新开会话” | 同一好友私聊长期共用会话键，上下文会持续拖拽文风与剧情 |
| 不敢删记忆做测试 | 全清会伤陪伴连续性与长期事实 |
| 角色卡软分拍被旧上下文压过 | 无历史时能空行分拍，有长 RP 历史时易退回一段式 |
| 已有压缩偏“存档”，缺少“换场” | `compress_session` / `clear_session` 可复用，但缺主人可感知的换话题产品语义 |

---

## 3. 非目标（本阶段明确不做）

1. 不删除、不改写手动长期记忆（`manual_memory` / LTM）。
2. 不删除历史正式会话摘要库中的旧摘要（可选择不再注入最近几条以外的内容，但不做物理清档）。
3. 不做自动话题检测（不在主人没说换场时偷偷重置）。
4. 不在三人群 SceneHub 默认启用（群聊另案；避免误切双角色公开场）。
5. 不把场景摘要自动升级为长期记忆。
6. 不做跨人格共享换场（默认人格换场不影响独立人格会话，反之亦然）。
7. 不在本阶段实现分镜多气泡发送（可后续叠加）。
8. 不要求主人删除数据库或执行危险运维命令。

---

## 4. 名词

| 名词 | 含义 |
|---|---|
| 短时原文窗口 | `messages` 表中该 `session_key` 的近期 raw 消息 |
| 正式会话摘要 | 现有 `session_summaries`，偏长期归档大意 |
| 空窗场景摘要 | 现有 `gap_scene_summaries`，桥接未进最近 N 条的中间段 |
| 话题场景摘要 | **本设计新增语义**：因主人主动换场而生成的“当前场景结束摘要” |
| 换场 | 摘要当前短时场景 + 清空短时原文 + 下轮按新场景开聊 |
| 续场 | 可选：根据最近一条话题场景摘要回到上一场景（二期） |

说明：话题场景摘要优先复用 `session_summaries` 存储，并通过 `source_kind` / 前缀标签区分；若首期不想改表，可用摘要正文固定头标记实现，二期再结构化。

## 5. 权限与作用域

### 5.1 谁能触发

- 仅主人。
- 仅私聊（`message_type=private`）。
- 默认启用对象：主人与某人格的私聊 runtime session（persona v2 session_key）。
- 非主人、群聊、控制台工具链：本阶段忽略或仅只读诊断。

### 5.2 作用会话

- 只影响**当前会话键** `conversation_scope(...).runtime_session_key`。
- 默认人格私聊换场 ≠ 独立人格私聊换场。
- 不触碰其他 bot / 其他用户会话。

### 5.3 开关

建议配置（名称可最终微调）：

```text
ENABLE_TOPIC_SCENE_SWITCH=true
TOPIC_SCENE_SWITCH_OWNER_ONLY=true
TOPIC_SCENE_SWITCH_PRIVATE_ONLY=true
TOPIC_SCENE_MIN_SOURCE_MESSAGES=4
TOPIC_SCENE_CONFIRM_REQUIRED=false
TOPIC_SCENE_USER_ACK=true
```

`TOPIC_SCENE_MIN_SOURCE_MESSAGES`：短时原文少于此数时，可只清空/提示“几乎没有可归档内容”，不必强行调用摘要模型。

## 6. 触发合同

### 6.1 自然语言触发（推荐）

整句或明显独立意图（避免误伤剧情对白里的“换个话题玩玩”）：

**硬触发（高置信，可直接执行）**

- `换个话题`
- `换话题`
- `聊点别的`
- `先到这里`
- `先这样吧，换一段`
- `新开一段`
- `重新开始这段`
- `这段先结束`
- `清空短时上下文`（高级，仍不删长期记忆）

**软触发（需更严格匹配，首期可只做硬触发）**

- `我们换个话题吧`
- `别续着刚才了`
- `当新的一段来`

### 6.2 命令触发（可选，与自然语言等价）

```text
/换话题
/新开一段
/场景重置
```

仅主人私聊。

### 6.3 不触发

- 角色扮演对白内部提及“换话题”但前后仍是剧情文本（首期用“整句匹配 / 命令优先”规避）。
- 非主人。
- 群聊。
- 仅包含这些词的更长剧情句（首期宁可漏触发，不可误触发）。

### 6.4 触发后的消息是否还送去角色聊天

```text
默认：换场请求本身不进入角色 RP 续写。
流程：识别 → 执行换场 → 系统短确认（可人格化包装）→ 本轮结束。
主人下一条消息才是新场景第一句。
```

若主人同一条消息写成：

```text
换个话题。今天想吃什么？
```

首期建议：

1. 先换场；
2. 把后半句当作**新场景首条用户消息**继续聊（可选增强）。
最小实现可要求分两条发：先换场，再发新内容。

## 7. 主流程（实现合同）

```text
1. 鉴权：主人 + 私聊 + 开关
2. 解析触发：硬触发 / 命令
3. 读取当前 session_key 短时原文
4. 若原文条数 >= MIN：
     a. 生成话题场景摘要（专用 prompt，不是普通流水账摘要口吻也可）
     b. 写入 session_summaries（标记 kind=topic_scene 或正文头标记）
     c. 可选：同步 MemoryRAG（沿用 summary 写入钩子，失败不得回滚换场）
5. 清空短时原文 messages（该 session_key）
6. 清空 gap_scene_summaries（该 session_key）
7. 不删除：manual LTM、历史 session_summaries、角色卡、配置
8. 写入运行时标记：topic_switch_epoch / last_topic_scene_summary_id
9. 回复主人确认语（短）
10. 结束本轮；下一条用户消息按“换场后首轮”组装上下文
```

### 7.1 与现有函数关系

| 能力 | 现有 | 换场用法 |
|---|---|---|
| 正式压缩 | `compress_session` | 可参考其“格式化消息 + summarize + 删原文”模式；换场更像 **force 归档当前窗口**，但摘要 prompt 用场景版 |
| 清短时 | `clear_session` | 换场成功后复用其“删 messages + 清 gap”语义 |
| 正式摘要存储 | `add_summary` | 存话题场景摘要 |
| 历史组装 | `build_history` | 换场后仍注入摘要/LTM；短时原文为空或仅新消息 |

注意：`clear_session` 今日会清 gap 且保留 formal summaries，方向正确；换场应在 clear 前先写出本轮 topic summary。

### 7.2 摘要失败时的失败策略

```text
优先 fail closed 且可预期：

A. 摘要模型失败 / 空摘要：
   - 不删原文（避免“失忆又无归档”）
   - 回复：换场失败，短时上下文仍保留，请稍后重试
   - 记 reliability / error log

B. 摘要成功但 clear 失败：
   - 保留已写入摘要
   - 回复：已归档但重置未完成，请重试“换话题”
   - 重试时应避免重复生成完全相同摘要（可用 message id 范围去重）

C. 原文过少：
   - 可直接 clear 或不 clear，只回复“当前几乎没有需要归档的短时内容，已按新话题处理”
```

首期推荐：**摘要失败不 clear**。

## 8. 话题场景摘要内容合同

### 8.1 摘要应包含

- 场景类型：日常陪伴 / 旅行 / 工作倾诉 / 亲密 RP 等（粗类即可）
- 已发生的稳定状态变化（关系态度、约定、未决问题）
- 主人明确要求记住的点（若有）
- 结束原因：主人主动换场

### 8.2 摘要应避免

- 逐句复述成人细节与可高危敏感描写（用“亲密互动已结束”等概括）
- 把猜测当事实
- 把临时 RP 身份写成永久设定
- 写入另一人格的私聊内容

### 8.3 摘要长度

- 建议 120～400 中文字符（可配置）
- 宁短勿散文还原

### 8.4 存储标记（首期最小）

摘要正文前缀：

```text
【话题场景摘要｜主动换场】
...
```

二期可加列：

```text
source_kind = topic_scene_switch
trigger = natural|command
message_start_id / message_end_id
```

## 9. 换场后的上下文组装合同

换场成功后的下一轮 `build_history` 语义：

```text
系统规则
角色卡
手动长期记忆
最近正式会话摘要（可包含刚写入的话题场景摘要）
（可选）仅 1 条“刚刚结束的场景”提示
短时原文：空，或仅有换场后的新消息
当前用户消息
```

额外 system 提示（建议，短）：

```text
主人已主动结束上一短时场景并开启新话题。
不要默认续写上一场景的动作、姿势或未完成 RP。
若新消息未提及旧场景，按新场景自然开聊；
仅当主人明确要求“接着刚才”时再回到上一场景摘要。
```

该提示可在换场后 **N 轮内** 带上（如 1～3 轮），避免永久污染。

## 10. 对主人的确认回复

### 10.1 默认系统短回（首期可用中性）

```text
好，上一场景我先收束归档了。短时上下文已重置，长期记忆还在。
你直接说下一句，我们开新的一段。
```

### 10.2 可选人格化包装（二期）

- 默认人格 / 独立人格用各自语气说“好，我们换一段”
- 但仍必须语义包含：已归档、未删长期记忆、请发下一句

### 10.3 不在确认语里

- 倾倒完整摘要正文（默认可不展示；调试命令可查看）
- 暴露 session_key / 数据库路径 / 消息 id

## 11. 与“重逢感 / 分拍测试”的关系

| 能力 | 关系 |
|---|---|
| 私聊节拍软规则 | 换场后短时历史变薄，软规则更容易生效，便于测试空行分拍 |
| 分镜多气泡发送 | 换场不依赖分镜；分镜是发送层后续 |
| 空窗摘要 | 换场时清 gap，避免旧空窗状态拖进新话题 |
| 删除记忆 | **禁止**作为测试或换场手段写进产品路径 |

验收上可用：

1. 进入长 RP；
2. 主人：`换个话题`；
3. 再发多拍日常/成人请求；
4. 期望：不再强行续写旧姿势/旧场景，且中长回复更易出现空行分拍。

---

## 12. 可选二期：续场

触发：

- `接着刚才`
- `回到上一段`
- `继续之前的场景`

行为：

- 读取最近一条 `topic_scene` 摘要注入
- 不自动恢复被清空的 raw 原文
- 角色按摘要续，不假装拥有被清空的逐字细节

首期可不做，但摘要存储格式要为它留标记。

---

## 13. 安全与隐私

1. 仅主人私聊。
2. 摘要与日志不得进入 Git。
3. Owner Console / 诊断若展示，只给元数据（时间、条数、kind），默认不给成人细节全文。
4. reliability 事件只记成功/失败原因码，不记原文。
5. 换场不是提权写盘到角色卡，不触碰 `prompts/persona-cards/private`。

## 15. 验收标准

### 15.1 功能

1. 主人私聊硬触发可换场。
2. 换场后 raw messages 数为 0（或仅含换场后新消息）。
3. 至少新增 1 条带换场标记的摘要（源消息足够时）。
4. 手动长期记忆条数不变。
5. 历史 formal summaries 不被批量删除。
6. 另一人格会话不受影响。
7. 非主人无法触发。

### 15.2 体验

1. 主人收到明确确认：已换场且长期记忆仍在。
2. 下一条新话题不会默认续写旧 RP 动作链。
3. 换场本身不产生长篇角色剧情续写。

### 15.3 失败

1. 摘要失败时原文仍在。
2. 有错误可诊断，不静默丢上下文。

### 15.4 回归

1. 普通聊天、自动压缩、空窗摘要、LTM 注入仍按原合同工作。
2. 群聊 / SceneHub 无行为变化。

## 16. 分阶段实现

### Phase 0（本合同）

- 冻结语义与非目标
- 不改代码

### Phase 1（最小可用）

- 硬触发 + 可选 `/换话题`
- 场景摘要 prompt + `add_summary` 前缀标记
- clear messages + clear gap
- 中性确认回复
- 换场后 1～3 轮 system 提示“勿默认续旧场景”
- 单元测试：触发识别、失败不 clear、会话隔离

### Phase 2

- 同句“换话题 + 新内容”拆分
- 人格化确认语
- `接着刚才` 续场
- 结构化 `source_kind`
- Owner Console 只读展示换场元数据

### Phase 3（可选）

- 与分镜发送联动
- 三人群“场次重置”另案评估

## 17. 测试计划（不删库）

### 17.1 自动化

- 触发词表正/反例
- mock 摘要成功 → 断言 messages 清空、summary +1、LTM 不变
- mock 摘要失败 → 断言 messages 不变
- persona A 换场不影响 persona B

### 17.2 人工 QQ

1. 与默认人格进入中长陪伴或 RP。
2. 发送：`换个话题`。
3. 确认回复符合合同。
4. 发送新的日常多拍请求，检查是否仍强行续旧场景。
5. 发送：`/记忆` 或既有诊断，确认长期记忆仍在。
6. 独立人格会话重复 2～5。

### 17.3 与无记忆探针关系

- `tmp/test_persona_soft_rules_no_memory.py` 继续用于角色卡分拍回归。
- 换场后的 QQ 行为应逼近“薄历史 + 摘要背景”，而不是完全无摘要的冷启动。

1. 同句“换个话题。今天想吃什么？”首期是否支持拆分续聊？

   - 默认建议：Phase 1 中性，Phase 2 人格化。

   - 默认建议：不可见，仅后台；`/场景摘要` 调试命令可选。
4. 成人场景摘要的概括强度？
   - 默认建议：强概括，不写细节动作链。
