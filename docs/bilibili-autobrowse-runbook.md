# 默认人格自动浏览与主动分享

2026-10-22：实现独立常驻进程，复用专用 Edge、角色卡、QQ 记忆、字幕校验、观影小记与已绑定主人私信线路。
只有实际启动后才会自动工作；安装代码不等于已经启动。

## 默认规则

| 项目 | 默认行为 |
|---|---|
| 浏览时机 | 首次启动且不在休息时段时先运行一轮，之后随机间隔 90–180 分钟 |
| 每日浏览 | 最多 6 轮，失败/中断的已预留轮次也计入，防止重启反复花费 |
| 单轮规模 | 首页/关注各最多 3 条候选，最多精选 1 条进一步读字幕 |
| 每日分享 | 北京时间自然日最多主动分享 3 条，不要求发满 |
| 分享间隔 | 两次主动视频分享至少相隔 2 小时，跨日也遵守 |
| 休息时段 | 北京时间 00:00–09:00 不浏览、不主动分享；恢复时加 0–60 分钟随机偏移 |
| 达分享上限 | 仍可在剩余浏览轮次中更新观影小记；不继续发送 |
| 专用 Edge 已关闭 | 到下一轮浏览时尝试打开原专用会话，再核对登录账号；已运行则复用 |
| 异常 | 本轮不重试，错误/风控/发送结果未知后至少等待 4 小时 |
| 睡眠/停机/重启 | 不补跑错过的多轮，保留下次时间及当日额度 |

自动浏览默认最多 12 次聊天模型请求/日（6 轮 × 初筛和单片理解各一次），没有新增独立日记模型请求。
该数量不包含已有记忆检索的 embedding；无新候选、未选片或无字幕会减少实际聊天调用。
角色卡、QQ 记忆长度及字幕会影响 token 数，不能用调用次数推算固定费用。

首页请求使用持久递增的 `fresh_idx`，服务器仍可能返回旧候选；本地另过滤最近 7 天已评估/已理解的 BVID。
候选因此全部跳过时不调用聊天模型。字幕失败的精选不会被标成已经成功理解。
字幕身份、时间轴、引用和主题一致性校验继续生效，没有可靠内容就不生成可发送分享。
当前“浏览”指发现视频并阅读字幕理解内容，不代表播放画面、完整视听观看或提交播放心跳。

## 推荐启动方式

### 双击入口（推荐）

打开 `D:\AIchatbot`，双击根目录中的相应文件即可，无需输入命令：

- `启动B站自动浏览.cmd`：在后台启动，允许按既定额度主动私信分享；需要时打开专用 Edge 检查登录。
- `查看B站自动浏览状态.cmd`：用中文显示运行状态、下次计划时间与当天额度。
- `停止B站自动浏览.cmd`：提交停止请求并等待确认，已经停止时直接提示。当前请求尚未完成时会说明仍在收尾，不强杀进程。

关闭这些入口的提示窗口不会停止后台浏览；使用停止入口控制退出。停止不会关闭 Edge 或 QQ。
可右键这些文件创建桌面快捷方式；不要将 `.cmd` 文件本身移出项目目录。

### PowerShell 入口

在 PowerShell 中执行：

```powershell
Set-Location D:\AIchatbot
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-bilibili.ps1 -Background
```

脚本会复用或打开默认人格专用 Edge，检查其登录账号，创建缺失的默认配置，然后启动隐藏的独立工作进程。
若提示未登录，请在这个专用 Edge 中用默认人格账号扫码，再重新执行启动命令。
已经有工作进程时直接显示现有状态，不重复启动。
保持电脑运行、网络可用；默认人格专用 Edge 可以最小化，不用手动停在某个视频页。
如果关闭了专用 Edge，后台会在下一轮实际浏览前尝试打开原来的专用会话，继续使用原账号的登录资料。
登录失效或账号不符时不会继续读取视频或分享，需在专用 Edge 中重新登录默认人格账号；打开失败按异常规则至少等待 4 小时再尝试。
休息时段、轮次已满及已停止后台时不会为浏览重新打开 Edge。想停止自动浏览请使用停止入口，关闭浏览器不能代替停止后台。
后台方式启动成功后可以关闭启动用的 PowerShell 窗口；不会自动启动 QQ 或创建开机任务。

观察终端日志可使用前台方式，保留这个 PowerShell 窗口，按 Ctrl+C 停止：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-bilibili.ps1
```

只想自动浏览、生成小记和报告，暂不发私信：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-bilibili.ps1 -Background -PreviewOnly
```

前台试运行至多一轮，仍遵守休息时段、已保存的下次时间和每日预算：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-bilibili.ps1 -PreviewOnly -Once
```

`-PreviewOnly` 仍会消耗实际发生的模型用量、更新当天小记、浏览轮数及去重记录；它只关闭私信提交。
切换预览/发送模式需先停止原进程，再以新参数启动。

## 查看状态与停止

```powershell
.\.venv\Scripts\python.exe scripts\bilibili_autobrowse.py status
.\.venv\Scripts\python.exe scripts\bilibili_autobrowse.py stop
```

`status` 只读取本机数据和进程锁，不请求 B 站或模型；显示：

- `running` / `send_enabled`：进程是否运行、是否启用实际分享。
- `phase`、`last_result`、`last_delivery`：当前阶段及上一轮结果。
- `next_due`：北京时间下次浏览时间，`quiet_hours` 表示正在休息。
- `today`：今天已预留浏览轮数、已记录模型调用、供应商已报告 token，以及未知用量/未完成轮次。
- `share_quota`：已占用分享数、剩余数、冷却秒数，以及历史不确定记录占用数。

停止通常在等待期间 5 秒内响应；正在执行的请求允许收尾，不强杀进程。
在浏览完成后再次检查停止请求，避免继续开始分享；已发起的请求仍可能完成。
重复运行 `status`，确认 `running=false` 后即可再次启动。停止浏览进程不会关闭 Edge 或 QQ。

后台日志默认在 `%LOCALAPPDATA%\AIchatbot\bilibili\autobrowse.stdout.log` 和 `autobrowse.stderr.log`。
日志只写事件、状态、数量与时间，不打印视频草稿、角色卡、记忆、UID 或 Cookie。
每次后台启动会重新建立这两份运行日志；完整私人预览仍按原机制保存在 `previews/`。

## 调整运行参数

```powershell
.\.venv\Scripts\python.exe scripts\bilibili_autobrowse.py init
```

该命令显示配置路径和当前参数，仅在文件缺失时写入默认值，不覆盖已有配置。
默认文件为 `%LOCALAPPDATA%\AIchatbot\bilibili\autobrowse-config.json`。
若设置了 `AIKE_BILIBILI_HOME`，以命令输出的私人目录为准。

```json
{
  "min_interval_minutes": 90,
  "max_interval_minutes": 180,
  "max_rounds_per_day": 6,
  "per_source": 3,
  "max_selected": 1,
  "quiet_start_hour": 0,
  "quiet_end_hour": 9,
  "error_backoff_minutes": 240
}
```

修改后停止并重启工作进程。两个 quiet 小时相同表示关闭休息时段；支持例如 23–9 的跨午夜休息。
每日最多 3 条分享及两小时分享间隔在连接器发送账本中执行，不由浏览轮次参数放大。
手动 `preview --send-one` 和自动分享共用账本；主人主动私聊的普通回复不使用主动视频分享额度。

## 持久化与边界

私人目录新增 `autobrowse.sqlite3`、`autobrowse-session.json`、`autobrowse.lock` 及停止信号文件。
浏览状态按已有跨平台身份摘要隔离；活跃进程由操作系统文件锁识别，不盲信旧 PID，也不自动杀进程。
每轮先保存预算占用和下次时间，再读取视频与调用模型；未知或崩溃的轮次不自动回放。
同一目录仅允许一个自动浏览进程，浏览器本身仍由既有控制锁串行访问。

发送账本在同一 SQLite 事务内预留视频身份、每日额度与冷却时间，之后才允许提交私信。
成功、发送中和结果未知均占用额度；明确被平台拒绝的失败释放额度，但同一个视频的投递键仍不重放。
旧报告只有匹配双方账号、BVID 和真实发送账本才补分类；无法辨认用途的旧成功/待定记录暂按可能分享保守占额，状态明确列出。
旧日不确定记录仍可能影响两小时冷却，不会因重启清空；记账按本地发起请求时间计算。

QQ 仍需自身正常运行并重载到已有记忆接入代码，才能在聊天中读取小记；刷视频进程不负责重启 QQ。
2026-10-23 已另增独立的主人文字私聊接收与回复进程，使用单独的启动/停止入口；详情见 [私聊回复说明](bilibili-inbox-runbook.md)。
