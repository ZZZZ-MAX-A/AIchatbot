# 聊天模型路由统一：第一阶段

更新日期：2026-10-11。

后续配置治理已实施，见 [配置治理与只读预检](configuration-governance.md)。下文记录第一阶段的路由边界。

本阶段修复实际聊天与诊断、配置展示、能力就绪判断之间的路由偏差。
`ENABLE_CHAT_GRAPH_RUNTIME` 只决定执行流程；它不决定接口、凭据、模型或超时。

## 生效规则

| 用途 | 选择规则 | 配置来源 |
| --- | --- | --- |
| 默认聊天 | 未指定角色或角色未命中专用路由允许列表 | `AIKE_LLM_*` |
| 角色普通聊天 | 专用路由已开启且角色卡键命中允许列表 | `PERSONA_LLM_*` |
| SceneHub 显式覆盖 | 调用方传入 `completion_route="legacy"` | `AIKE_LLM_*` |
| 摘要与记忆压缩 | 全角色共用独立摘要路由 | `SUMMARY_LLM_*` |
| MainAgent | 使用既有 MainAgent 配置 | `MAIN_LLM_*` |

独立人格普通聊天与 SceneHub 的区别继续存在：SceneHub 的独立人格演员由
`scene_actor_profile.py` 显式选择 `legacy`，保留低推理强度和原来的角色提示策略。
角色身份、记忆受众、会话键、数据库范围、主人权限由既有业务层处理，不由模型路由解析器改写。

`CHAT_LLM_*` 字段继续兼容读取，当前不参与生产聊天、LangChain 聊天构造器或聊天健康探针的选择。
无需为启用 ChatGraph 向这些字段复制凭据。第一阶段不删除字段、不迁移 `.env`；旧字段的完整弃用流程留到配置治理阶段。

## 代码入口

- `src/plugins/ai_chat/completion_routes.py`：纯路由解析、配置完整性检查和摘要路由。
  不导入 SDK、QQ 适配器、提示词文件或数据库模块，不发起网络请求。
- `src/plugins/ai_chat/llm.py`：真实聊天使用上述解析器；保留原导出名称，兼容已有调用方。
- `src/plugins/ai_chat/diagnostics.py`：配置告警、模型详情、就绪判断、配置摘要和聊天探针使用上述解析器。
- `src/plugins/ai_chat/owner_console_read_runtime.py`：控制台聊天模型快照读取默认生效路由。
- `src/plugins/ai_chat/owner_console_fastapi_app.py`：只读诊断分别报告执行链路、模型路由和配置完整性。
- `src/plugins/ai_chat/__init__.py`：QQ 状态、诊断图快照、模型配置摘要和系统诊断能力判断使用上述解析器。
- `src/plugins/ai_chat/lc/models.py`：聊天模型构造器接受角色和显式路由覆盖，使用同一个解析器。

控制台的全局 `chat_model` 是默认路由快照，缺少 QQ 事件的角色与场景上下文。
`active_role_card_key` 是默认账号固定角色卡的兼容字段；各账号的固定绑定、模型和记忆模式
见设置快照的 `persona_bindings`。完整边界见 [账号固定人格与维护边界](fixed-persona-maintenance.md)。
网页将这些字段标为“默认聊天模型”；角色普通聊天和 SceneHub 的覆盖规则需分别判断。

## 配置和探针边界

默认聊天的完整性检查包含凭据、接口地址、模型、正数超时。
角色路由另检查支持的提供方；Ollama 路由不要求 API Key，但要求有效的上下文、输出上限和保活配置。
已启用且命中的角色路由缺项时停止调用，继续保留“不回退其他模型”的行为。

`check_chat_api(config, role_card_key="", completion_route="auto")` 每次只检查一个生效路由：

1. 先检查配置；不完整时返回字段名，不发起模型请求。
2. 使用固定的公开测试提示词，不读取聊天记录或私人提示词，不启用工具。
3. OpenAI 兼容接口使用相同的接口、模型和凭据；探针超时上限为 5 秒，SDK 自动重试关闭。
4. Ollama 使用原生 `/api/chat`，限制测试输出并在请求完成后卸载本次探针模型。
5. 失败不尝试其他接口，空文本视为检查失败。

`format_diagnostics` 默认只探测默认聊天路由；不会因为多个角色已配置而自动增加远程调用。
HTTP 控制台诊断仍是只读配置快照，不主动探测模型服务。
LangChain 构造器只支持 OpenAI 兼容接口；传入原生 Ollama 路由会明确报错，原生调用继续使用 `ask_llm`。
