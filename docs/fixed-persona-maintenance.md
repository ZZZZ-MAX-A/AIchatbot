# 账号固定人格与维护边界

每个运行中的机器人账号必须通过 `BOT_PERSONA_BINDINGS` 显式绑定人格和角色卡。
格式仍为 `bot_self_id=persona_id:role_card_key`，分号分隔。绑定在部署配置中维护，
配置文件变更需要重启进程；运行时不提供切卡功能。

## 身份与存储

固定身份独立于 Persona V2 运行和记忆开关。与 `LEGACY_PERSONA_ID`、
`LEGACY_ROLE_CARD_KEY` 同时匹配的显式绑定，可以继续使用默认聊天模型、
`data/chatbot.db` 和既有 private/group 会话键。其他身份必须进入显式允许的 V2
路由，继续使用 `persona:<persona_id>:<原会话键>`。V2 持久记忆仍保存在
`data/persona-memory/<persona_id>.db`；关闭持久记忆的有效 V2 账号保留进程短时记忆。

本次不迁移、清理或重建历史数据。人格摘要继续使用共享的 `SUMMARY_LLM_*`。
默认人格固定卡优先保留 `AIKE_LLM_*`，不会因为提供了显式角色卡 key 而命中
另一人格的模型白名单。独立人格普通聊天与 SceneHub 的模型差异继续保留。

默认人格普通聊天显式传递固定卡，但通过 `include_world_card=False` 保留原有独立世界卡
加载策略。SceneHub 和独立人格继续使用原有世界卡策略。增加默认人格普通聊天的共同世界事实
属于独立的回复行为变更，后续应单独验证。

## 失效规则

- 未绑定账号、缺失/空白/不可读的绑定卡、无效 V2 路由与记忆组合均使该作用域无效。
- 不同角色卡不得共用同一 `persona_id`。绑定语法或一致性错误使绑定配置失败关闭。
- 非默认人格关闭 V2 后不会进入默认记忆库。
- 角色文件按明确 key 加载；坏的私有覆盖不会借用公开同名卡，也不会扫描其他卡来选择替代。
- 普通聊天、语音聊天准备、重置、话题切换、记忆查询/管理、诊断和记忆写入均检查作用域。
- 审批恢复执行再次按存储的会话键校验当前绑定和持久记忆条件；过时 V2 目标不能解释为默认库。
- 后台压缩和聊天持久化校验目标，继续使用任务局部的数据库上下文。

群私聊记忆受众边界、主人权限以及 SceneHub 特定群和成员检查继续保留。
共享场景演员也校验实际发送账号的固定身份，再读取连续性背景或调用模型。

## 切卡入口

`/选择角色卡` 和别名保留为阻止切换的提示命令。MainAgent 不再公布或批准
`select_persona`；Web 审批恢复白名单也移除它。执行层和底层选择函数分别阻止
旧调用，已有切卡审批可以拒绝，不能继续切换。

`data/active-role-card.json` 保留在本地，但不再影响运行身份；配置失效时不再选择
列表中的第一张卡。默认卡兼容读取函数只按配置的默认卡 key 加载。

## 只读维护证据

`persona_maintenance.py` 为启动预检、QQ 人格状态与 Web 设置提供相同的绑定总览。
总览包括账号序号、人格、卡可用性、模型、存储模式和错误代码，不输出账号号码、
凭据、角色正文、标题或私人文件路径。

`python scripts/check_configuration.py --require-chat` 同时检查默认聊天线路与全部
已配置绑定。`start.ps1` 在端口探测和服务启动之前拒绝未就绪的绑定。
预检只验证本地配置和卡文件；不导入 Bot、数据库或模型客户端，不验证外部服务在线。

Web 设置最初提供“账号固定绑定”只读总览，现已扩展为账号下的人格配置卡片，
分别展示聊天/视觉模型、音色试听、记忆库归属和能力差异。参见
[账号人格配置可视化](account-persona-configuration-view.md)。配置编辑和实际在线状态
验收仍属于后续阶段。

## 验证

新增测试覆盖固定身份、旧库/独立库目标保持、异常时阻止读写、配置变更后的审批、
切卡审批失效、语音入口、默认模型保护、世界背景加载策略和角色文件失败处理。
前端测试覆盖按账号显示固定卡、模型、记忆方式和不可用状态。
