# 默认人格 B 站私聊接收与文字回复

2026-10-23：方案 A 的第一阶段，复用默认人格专用 Edge 登录会话收发消息，新增独立私聊监听进程。
只处理已绑定主人与默认人格的单人会话，不读取其他会话，也不需要导出 Cookie。

## 使用方式

打开 `D:\AIchatbot`，双击：

| 入口 | 操作 |
|---|---|
| `启动B站私聊回复.cmd` | 后台开启收件和真实文字回复 |
| `查看B站私聊回复状态.cmd` | 查看监听状态、下一次检查时间、待处理/已回复/结果不明的数量 |
| `停止B站私聊回复.cmd` | 请求停止，等待当前操作收尾，不关闭浏览器或 QQ |

自动浏览与私聊回复是独立开关：原来的自动浏览启动/停止入口只控制刷视频。
关闭任一提示窗口不等于停止对应后台；重复启动不会创建第二个监听进程。
只要任一后台仍在工作，浏览器关闭后仍可能被它重新打开；想完全停止 B 站活动，应分别停止两个后台。
私聊回复没有夜间休息限制；它回应主人主动消息，不占每日三条主动视频分享额度。

也可以使用 PowerShell：

```powershell
Set-Location D:\AIchatbot
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-bilibili-inbox.ps1 -Background
.\.venv\Scripts\python.exe scripts\bilibili_inbox.py status
.\.venv\Scripts\python.exe scripts\bilibili_inbox.py stop
```

前台观察事件日志可省略 `-Background`。直接 `run` 同样会启用真实回复，不是预览命令。
`scripts/bilibili_inbox.py start` 也是后台真实回复入口；子进程关闭继承句柄并单独记录日志，启动命令返回后继续工作。

## 收件规则

- 平时随机每 30–60 秒检查一次；正常空轮询不请求聊天模型或 embedding。
- 接口读取逐条消息，不依赖“未读”标记，也不是只取会话最后一句；主人用手机读过不会影响增量识别。
- 第一次启用先建立当前位置，不补答旧消息；已经建立后，重启保留接收进度和本地未处理队列。
- 发现消息后等候约 4 秒并再检查一次，以合并连发消息；持续输入最多合并 15 秒，每批最多 10 条/约 8000 字。
- 消息按平台编号排序，分页直到已保存的位置。一次同步最多 20 页；不能完成时保留旧游标，不跳过中间内容。
- 已收到的队列保存在本机私人目录，只有绑定主人的真实文字能作为当前输入。
- 撤回/不可用消息不会作为有效内容回复；暂不保证把平台后来撤回的旧消息从既有记忆自动删除。

浏览器不存在时尝试打开原专用会话。账号检查、收件和发送均使用浏览器内登录状态。
未登录、账号不符或普通读取异常，默认等待 15 分钟；明确 412/429 或风控业务码至少等待 4 小时。
浏览器被本地另一任务占用，先等待控制锁，仍忙时按短间隔重查，不当作平台风控。
错误等待时间会保存，重启不会清空等待时间。重新登录后也需等到状态显示的下一次检查。

## 回复与记忆

新增专门的 `reply` 模型任务，按同一角色卡自然回答；当前主人消息与历史背景分开。
每批通常一次聊天模型请求，最多发送一条 300 字以内的文字；模型用量存入私人批次记录。
QQ 记忆沿用现有只读读取规则，B 站近期三轮和独立最多五条语义召回补充本平台背景；相关时读取今天的小记。
新收到的主人消息和平台已接受的默认人格回复进入 B 站独立历史与索引。
QQ 侧仍沿用已约定的最近三轮、RAG 最多五条及原背景预算，不改 QQ 原文表、摘要、长期记忆提取或配额。

第一阶段支持文字聊天。视频链接按文字接收，尚未接入主人分享视频后的字幕理解；图片、语音及视频卡片也未解析。
没有验证过的视频内容不会交给模型当作已看事实；模型被明确要求不得凭链接编造观看感受。
后续视频回复属于第二阶段，不能把本阶段的普通文字回复当成已经具备完整视听理解。

## 防重复与恢复

收件、游标推进在同一事务中保存，消息编号与消息身份均去重。
每批先占位再生成，草稿先保存再发送；生成中进程中断会标记 `interrupted`，不自动再花一次模型用量。
发送使用原 `deliveries.sqlite3` 中稳定的批次投递键，`pending` / `unknown` 不能自动重发。
明确失败也保留失败状态，不自动对同一消息反复回复；主人可以再发一条新的消息继续对话。
重启时，已确认成功的发送账本可补回留存，不重复发信；只能恢复请求发起时间时，按 `send_attempt` 记录，不伪称平台送达时间。
停止期间若已有草稿保存但尚未发送，后续重新启动可继续发送该草稿；停止前已经提交的请求可能完成。

浏览器读写按短操作持有控制锁，耗时模型生成在锁外，避免刷视频全程阻塞收件。
不需要为了启用监听重启 QQ；QQ 是否已载入此前的 B 站背景读取代码，应按其实际运行版本核对。

## 本地数据与排障

默认私人目录 `%LOCALAPPDATA%\AIchatbot\bilibili`，可由 `AIKE_BILIBILI_HOME` 指定。
新增 `inbox-config.json`、`inbox.sqlite3`、`inbox-session.json`、`inbox.lock` 和停止信号文件。
`inbox.stdout.log` / `inbox.stderr.log` 为后台日志，记录阶段、数量和脱敏错误类型，不打印私信、记忆、角色卡或凭据。
数据库含真实私聊和草稿，不得提交到 Git 或公开分享。后台启动会重建运行日志，消息和批次数据库不清空。

`status` 的 `last_result=poll_failed` / `blocked` 表示等待重查；`last_error_kind` 是脱敏异常类型。
`generation_failed`、`interrupted`、`failed`、`unknown` 是保留的失败或不确定状态，不应通过删除账本来强行重发。
状态中的“已回复”只代表平台接口接受，不代表主人已读。
